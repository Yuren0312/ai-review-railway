# Rules

This document defines the **decision rules and thresholds** of `ai-review-railway`. Everything can be overridden in `.ai-review-railway.yml`.

## 1. AI-PR detection (six signal families, any hit flags it)

| Signal | Trigger | Example |
| --- | --- | --- |
| `label` | a PR label matches `ai.labels` (`ai`/`ai-generated`/`bot`/`copilot`/`claude`/`gpt`/`openai`/`automated`) | `ai-generated` |
| `author` | `author.type === 'Bot'`, or the author name matches `bot|robot|automation|ai|agent`, or is in `ai.authors` | `gpt-bot` |
| `trailer` | a commit message contains `Generated-by:` / `Co-authored-by:` / `Ai-assisted:` etc. | `Generated-by: claude-3` |
| `template` | the PR body has a checkbox (`- [x]`) next to an AI-declaration keyword | `- [x] This PR was generated by AI` |
| `keyword` | title/body contains `generated by` / `ai-generated` / `automatically generated` etc. | `automatically generated` |
| `generative_trace` | the body has ≥3 structured headings (Summary/Changes/Test Plan…) | typical AI template structure |

> **Agent identity**: prefers the generator name from a trailer (e.g. `Generated-by: claude-3` → `claude-3`), otherwise falls back to the PR author.

## 2. Rate-limit rules

| Config key | Default | Meaning |
| --- | --- | --- |
| `per_agent_per_day` | 3 | max PRs from the same agent per 24h |
| `per_repo_per_day` | 10 | max PRs in the repo per 24h |
| `per_author_per_day` / `per_agent_per_hour` / `per_repo_per_hour` / `per_author_per_hour` | `null` (off) | optional extensions |
| `max_files` | 20 | file-count threshold per PR |
| `max_additions` | 500 | additions threshold per PR |
| `max_deletions` | 500 | deletions threshold per PR |

**Over-limit handling**: auto-comment + `needs-guarantor` label, **never closes**.

## 3. Risk classification (`railway:low/medium/high`)

Priority from high to low; the first match decides (high wins):

1. **`high`**: matches `high_paths` / dependency files / workflow files / auth·permission·secret files.
2. **`medium`** (when no high match): matches `medium_paths`, or file count / +/- lines exceed thresholds, or AI-generated with ≥3 files.
3. **`low`**: everything else.

**Escalation rules**:
- Matching `require_tests_for` but no test evidence → records a blocker (level unchanged, "missing tests" is noted).
- CI status is failure → escalate one level.

**Sensitive-path defaults** (overridable in `risk.*`):
- `high_paths`: `.github/workflows/**`, `package.json`, `requirements.txt`, `pyproject.toml`, `**/auth/**`
- `dependency_paths`: `package*.json`, `yarn.lock`, `requirements*.txt`, `pyproject.toml`, `go.mod/sum`, `Cargo.toml/lock`, `Gemfile*`, `composer.*`, `pom.xml`, `build.gradle*`, `Dockerfile`…
- `workflow_paths`: `.github/workflows/**`, `.github/actions/**`, `action.yml`
- `auth_paths`: `**/auth/**`, `**/authorization/**`, `**/rbac/**`, `**/credentials*`, `**/*.key`, `**/secrets*`, `**/.env*`, `**/*.pem`

## 4. Human-guarantor rules

- When `guarantor.required_for` contains the current risk level, the PR must bind a human guarantor.
- Two ways to satisfy (either is enough):
  1. the PR carries `guarantor.approved_label` (default `ai-guarantor-approved`);
  2. a **non-Bot** user comments `guarantor.command` (default `/guarantee`).
- Unsatisfied → apply `needs-guarantor` and explain how to guarantee in the comment.

## 5. Sandbox / allow-list

- `sandbox.allow_repos`: when non-empty, only these `owner/repo` are in scope.
- `sandbox.allow_branches`: when non-empty, the PR's head/base branch must match (default `ai-sandbox/*`).
- `sandbox.enforce`: `true` treats a mismatch as a blocker; `false` (default) only warns.

## 6. Parallel fallback (not configurable)

- AI auto-pre-review **always** coexists with human final review: the action only labels + comments, and **never merges, never closes**.
- Merging a high-risk PR is always done by a human (combined with branch protection).

## 7. Safety red lines (not overridable)

- Default `observe` mode; `enforce` only means "advisory blocking" — it **never close / merge / push**.
- No checkout, no executing PR code, no dependency install.
- No bypassing the repo's existing rules (it layers on top of CI / branch protection).
