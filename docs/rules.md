# 规则（Rules）

本文档定义 `ai-review-railway` 的**判定规则与阈值**。所有规则都可通过 `.ai-review-railway.yml` 覆盖。

## 1. AI PR 识别（六类信号，命中任一即判定）

| 信号 | 触发条件 | 示例 |
| --- | --- | --- |
| `label` | PR 标签命中 `ai.labels`（`ai`/`ai-generated`/`bot`/`copilot`/`claude`/`gpt`/`openai`/`automated`） | `ai-generated` |
| `author` | 作者 `type === 'Bot'`，或作者名命中 `bot|robot|automation|ai|agent` 正则，或在 `ai.authors` 名单 | `gpt-bot` |
| `trailer` | commit 信息含 `Generated-by:` / `Co-authored-by:` / `Ai-assisted:` 等 trailer | `Generated-by: claude-3` |
| `template` | PR 正文有模板勾选（`- [x]`）+ AI 声明关键词 | `- [x] 此 PR 由 AI 生成` |
| `keyword` | 标题/正文含 `generated by` / `ai-generated` / `automatically generated` 等 | `automatically generated` |
| `generative_trace` | 正文含 ≥3 个结构化小节标题（Summary/Changes/Test Plan…） | AI 常见模板结构 |

> **agent 身份**：优先取 trailer 中的生成者名（如 `Generated-by: claude-3` → `claude-3`），否则回退为 PR 作者。

## 2. 限流规则

| 配置项 | 默认 | 说明 |
| --- | --- | --- |
| `per_agent_per_day` | 3 | 同一 agent 24h 内 PR 数上限 |
| `per_repo_per_day` | 10 | 仓库 24h 内 PR 数上限 |
| `per_author_per_day` / `per_agent_per_hour` / `per_repo_per_hour` / `per_author_per_hour` | `null`（关闭） | 可选扩展 |
| `max_files` | 20 | 单 PR 文件数阈值 |
| `max_additions` | 500 | 单 PR 新增行阈值 |
| `max_deletions` | 500 | 单 PR 删除行阈值 |

**超限处理**：自动评论 + 打 `needs-guarantor` 标签，**不直接关闭**。

## 3. 风险分级（`railway:low/medium/high`）

优先级从高到低，命中即定级（高优先）：

1. **`high`**：命中 `high_paths` / 依赖文件 / workflow 文件 / 权限·认证·密钥文件。
2. **`medium`**（当未命中 high 时）：命中 `medium_paths`，或文件数/增删行超过阈值，或 AI 生成且改动 ≥3 个文件。
3. **`low`**：其余。

**提级规则**：
- 命中 `require_tests_for` 但无测试证据 → 记录阻断项（等级不变，标记「缺少测试」）。
- CI 状态为失败 → 提一级。

**敏感路径默认值**（可在 `risk.*` 覆盖）：
- `high_paths`：`.github/workflows/**`、`package.json`、`requirements.txt`、`pyproject.toml`、`**/auth/**`
- `dependency_paths`：`package*.json`、`yarn.lock`、`requirements*.txt`、`pyproject.toml`、`go.mod/sum`、`Cargo.toml/lock`、`Gemfile*`、`composer.*`、`pom.xml`、`build.gradle*`、`Dockerfile`…
- `workflow_paths`：`.github/workflows/**`、`.github/actions/**`、`action.yml`
- `auth_paths`：`**/auth/**`、`**/authorization/**`、`**/rbac/**`、`**/credentials*`、`**/*.key`、`**/secrets*`、`**/.env*`、`**/*.pem`

## 4. 人类担保规则

- `guarantor.required_for` 包含当前风险等级时，PR 必须绑定人类担保人。
- 两种满足方式（任一即可）：
  1. PR 被打上 `guarantor.approved_label`（默认 `ai-guarantor-approved`）；
  2. 有**非 Bot** 用户评论 `guarantor.command`（默认 `/guarantee`）。
- 未满足 → 打 `needs-guarantor`，评论中提示如何担保。

## 5. 沙盒 / 白名单

- `sandbox.allow_repos`：非空时，仅这些 `owner/repo` 生效。
- `sandbox.allow_branches`：非空时，PR 的 head/base 分支需命中（默认 `ai-sandbox/*`）。
- `sandbox.enforce`：`true` 时未命中即视为阻断；`false`（默认）时仅提示。

## 6. 兜底并行（不可配置）

- AI 自动预审 **永远**与人类最终 review 并存：动作只打标签 + 评论，**永不合并、永不关闭**。
- 高风险 PR 的合并必须由人类完成（配合分支保护规则）。

## 7. 安全红线（不可覆盖）

- 默认 `observe` 模式；`enforce` 也只是「提示阻断」，**绝不 close / merge / push**。
- 不 checkout、不执行 PR 代码、不安装依赖。
- 不绕过仓库既有规则（叠加在 CI / 分支保护之上）。
